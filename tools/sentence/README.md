# Сборка коротких предложений из распознанных слов

Этот набор скриптов делает **полностью оффлайновую** модель, которая по
последовательности слов, сохранённых в истории приложения, собирает короткое
русское предложение. Всё работает на телефоне, без сети, экспорта и облака.

Папка `E:\Programs\prilojuxa\predlojenia` — это Windows-junction на
`Sign-Language-Translator-restored\tools\sentence`. Физически файлы лежат в
репозитории приложения (ветка `message-db`), поэтому коммитить их нужно там.

---

## 1. Что уже сделано

- Написан генератор обучающих пар `build_pairs.py`:
  - вход — ровно те 100 слов, которые сейчас распознаёт приложение
    (`words.txt`, копия `app/src/main/assets/classes.txt`);
  - выход — короткие предложения из словоформ этих же слов и закрытого
    списка служебных слов;
  - есть шум: потеря слова, замена на соседнее по смыслу, дубликат,
    перестановка. Это имитирует неидеальное распознавание.
- Написан маленький seq2seq-трансформер `train_seq2seq.py`:
  - 4 слоя энкодера + 4 слоя декодера;
  - `d_model=192`, 6 голов, `dim_ff=768`, dropout 0.1;
  - около **5.24 млн параметров**, итоговый `.ptl` — примерно **21 МБ**;
  - кастомное attention на `bmm`/`softmax`, без `nn.MultiheadAttention` и
    `scaled_dot_product_attention`: приложение использует PyTorch Mobile Lite
    2.1.0, а часть fused-операций там недоступна.
- Написан экспорт `export_ptl.py`: `torch.jit.script` → `sent.ptl` +
  `vocab.txt`, со сверкой обычной и scripted-модели на `test.tsv`.
- Написаны проверки `check_data.py` и `smoke_test.py`.
- Сгенерирован и проверен smoke-набор `data_smoke` на 4000 пар:
  0 пустых выходов, 0 конфликтов «один вход — разные выходы»,
  0 токенов вне словаря. Словарь smoke-набора — 1885 токенов.
- `smoke_test.py` проверяет forward/backward, скриптование и сохранение
  `.ptl` без обучения; экспорт с случайным чекпоинтом уже проходил.
- Добавлена Android-интеграция: `SentenceBuilder.kt`, кнопка
  «Собрать предложение» в истории, диалог с результатом. Приложение
  собирается и без модели: кнопка показывает понятное сообщение.

**Обучение не запускалось.** Скрипты и инструкции готовы, но реальные веса
нужно получить самостоятельно командами ниже. Это заняло бы десятки минут
на GPU и не входило в задачу.

## 2. Важное ограничение

Это **не универсальный переводчик** и не языковая модель. Словарь выхода
закрыт: все формы 100 исходных слов плюс фиксированные служебные слова и
пунктуация. Модель физически не может написать слово, которого нет в
`vocab.txt`.

Поэтому пример «мама, мыть, рама → мама мыла раму» **сейчас невозможен**:
слов «мама», «мыть», «рама» нет среди 100 распознаваемых классов. Текущий
набор — животные, части тела, места, действия, признаки и категории
(лиса, волк, медведь, копыто, крыло, интеллектуальный, застенчивый,
«делать выводы» и т. п.).

Что модель умеет на этих словах:

- `волк + заяц` → `волк ест зайца .`
- `слон + копыто` → `у слона нет копыт .`
- `птица + гнездо` → `птица живёт в гнезде .`
- `тигр + застенчивый` → `тигр застенчивый .`
- `волк + кролик + лось` → `волк , кролик и лось .`
- `лиса + волк + дикое животное` → `лиса и волк — дикие животные .`

Списки и предложения с двумя животными сохраняют порядок, в котором слова
пришли из распознавания, а не сортируют их по внутреннему порядку.

- Windows (проверялось на Windows + PowerShell).
- Python 3.10–3.12. Проверено на Python 3.12.
- `pip install -r requirements.txt`.


## 6. Что делает каждый шаг

### 6.1. `build_pairs.py`

Генерирует пары «входные метки → предложение». Вход в TSV записывается через
`|`, например `волк|заяц`, выход — обычная строка с пробелами.

Шаблоны:

- одно слово (`лиса` → `лиса .`);
- животное + часть тела (`у птицы есть клюв .`, `у слона нет копыт .`);
- животное + место (`птица живёт в гнезде .`);
- животное + признак (`тигр застенчивый .`, `медведь добрый .`);
- животное + категория (`акула — водоплавающее .`);
- животное + характер (`лиса — проныра .`);
- два животных: хищник/жертва, заметная разница в размере, общая категория;
- два животных + категория (`лиса и волк — дикие животные .`);
- список из 3–4 животных (`волк , кролик и лось .`);
- действия (`корова виляет хвостом .`, `обезьяна делает выводы .`);
- специальные шаблоны (`паук плетёт паучью сеть .`, `пчела делает соты .`).

Шум:

- с вероятностью 8% теряется одно слово;
- иногда слово заменяется соседним по смыслу;
- иногда добавляется дубликат;
- порядок меток перемешивается.

Конфликты «один и тот же вход — разные выходы» отбрасываются. Поэтому
`check_data.py` должен показывать `входов с разными выходами: 0`.

Ключевые параметры:

```text
--words   words.txt      файл со 100 словами
--out     data           куда писать train/val/test/vocab
--count   150000         сколько уникальных пар хотим
--seed    42             воспроизводимость
```

Разбиение: 90% train, 5% val, 5% test. Для smoke-проверки достаточно
`--count 4000 --out data_smoke`.

### 6.2. `check_data.py`

Проверяет:

- пустые выходы;
- одинаковые входы с разными выходами;
- токены, которых нет в `vocab.txt`;
- распределение по шаблонам и длину предложений.

Хороший результат:

```text
пустых выходов: 0
входов с разными выходами: 0
токенов вне словаря: 0 []
```

Если появились конфликты — это баг в `resolve()`/шаблоне, а не в модели.
Исправлять нужно генератор, а не данные вручную.

### 6.3. `train_seq2seq.py`

Архитектура:

- общий словарь входа и выхода (размер ≈ 1.9–2.1 тыс. токенов; в smoke-наборе
  1885);
- `d_model=192`, `nhead=6`, `num_layers=4`, `dim_ff=768`, dropout 0.1;
- positional encoding синус/косинус;
- pre-norm residual блоки;
- жадное декодирование внутри модели: на вход `LongTensor [1, N]`, на выход
  `LongTensor [1, M]` с `<eos>`.

Обучение:

- `CrossEntropyLoss` с `label_smoothing=0.1`;
- AdamW, `lr=3e-4`, warmup 5% шагов, косинусное затухание;
- gradient clipping 1.0;
- на CUDA — `bfloat16` autocast;
- лучший чекпоинт выбирается по `exact match` на val (с небольшим штрафом за
  loss);
- ранняя остановка через `--patience 4`.

Параметры:

```text
--data data
--out checkpoints
--epochs 15
--batch 256
--lr 3e-4
--d-model 192
--layers 4
--heads 6
--ff 768
--dropout 0.1
--max-len 24
--seed 42
--device auto
--patience 4
```

Результаты:

- `checkpoints/best.pt` — лучший чекпоинт;
- `checkpoints/last.pt` — последний;
- `checkpoints/train_log.txt` — лог.

Ориентир по времени на RTX 5060 8 ГБ: десятки минут на 150 тыс. пар и
15 эпох. Точное время зависит от GPU, драйвера и загрузки.

Если CUDA OOM:

```powershell
python train_seq2seq.py --data data --out checkpoints --batch 128
```

Или уменьшить модель:

```powershell
python train_seq2seq.py --data data --out checkpoints `
  --d-model 160 --heads 4 --ff 640 --batch 256
```

После уменьшения модели чекпоинт всё равно экспортируется: конфигурация
сохраняется внутри `best.pt`.

### 6.4. `export_ptl.py`

- загружает `best.pt` на CPU;
- оборачивает модель в `Exported`, чтобы снаружи был просто `forward(src)`;
- делает `torch.jit.script`;
- сверяет eager и scripted на первых `--limit` примерах из `test.tsv`;
- сохраняет `sentence/sent.ptl` и копирует `sentence/vocab.txt`.

Ожидаемый вывод:

```text
Формат .ptl: bytecode=8, file=10
Проверено примеров: 200, расхождений eager/scripted: 0
Модель: ...\sentence\sent.ptl  (примерно 21 МБ)
Словарь: ...\sentence\vocab.txt
```

`Lite Interpreter is deprecated` — предупреждение, а не ошибка. Файл `.ptl`
создаётся и подходит для PyTorch Mobile Lite, который использует приложение.

PyTorch Mobile 2.1.0 поддерживает bytecode 4–9 и file format не больше 10.
Экспорт из PyTorch 2.11 обычно даёт `bytecode=8, file=10` — это совместимо.
Если скрипт печатает `ВНИМАНИЕ`, экспортируйте в отдельном окружении с
`torch==2.1.0` (Python 3.11): чекпоинт загружается и в более старом PyTorch,
потому что в нём только обычные тензоры и конфиг.

и перезапустите приложение: кэш обновляется из assets при первом нажатии,
очищать данные и терять историю не нужно.

## 8. Как устроена Android-часть

- `SentenceBuilder` лениво читает `assets/sentence/vocab.txt`, копирует
  `assets/sentence/sent.ptl` во `filesDir` и загружает его через
  `LiteModuleLoader`.
- Инференс и загрузка идут на `Dispatchers.IO` под `Mutex`.
- Вход: `BOS + id слов + EOS`; выход: id до первого `EOS`.
- `PAD/BOS/EOS` — 0/1/2, как в Python.
- Детокенизация: точка и запятая без пробела, тире с пробелами, первая буква
  заглавная.
- Если `sent.ptl` или `vocab.txt` нет, возвращается `SentenceResult.Failure`
  с инструкцией; приложение не падает.
- Кнопка блокируется на время сборки и показывает «Собираю…».

## 9. Ограничения и качество

- Только 100 слов. Новые слова появятся только после расширения словаря и
  переобучения.
- Шаблоны конечны. Необычная комбинация может дать странное, но грамматически
  допустимое предложение.
- Одно слово даёт однословное предложение (`Лиса .`).
- Списки сохраняют порядок распознавания.
- Модель не генерирует слова вне словаря — это сознательное решение против
  галлюцинаций.
- Сравнения размеров намеренно осторожные: сравниваются только классы,
  отличающиеся минимум на два, чтобы не получать «лягушка больше ежа».
- Качество оценивайте по `exact match` на val в `train_log.txt`. Если он
  низкий (например, ниже 80%), добавьте данные/эпохи или проверьте
  `check_data.py`. Не ориентируйтесь только на train loss.

## 10. Как расширять словарь

1. Добавьте слова в `words.txt` (сейчас скрипт требует ровно 100; при
   расширении снимите проверку `len(words) != 100` или измените её).
2. Опишите новые слова в `lexicon.py`: класс, совместимость, части тела,
   места, хищник/жертва, размер и т. п.
3. Добавьте шаблоны в `build_pairs.py`, если нужны новые конструкции.
4. Перегенерируйте данные и обучите модель заново.
5. Обновите распознавание: `app/src/main/assets/classes.txt` и саму
   100-словную модель. Это отдельная задача; текущая модель распознавания
   не менялась.
6. Скопируйте новый `sent.ptl`/`vocab.txt` в assets и пересоберите APK.

Важно: `vocab.txt` должен быть собран **тем же** запуском `build_pairs.py`,
что и данные обучения. Не перегенерируйте словарь после обучения.

## 11. Частые проблемы

**`ModuleNotFoundError: No module named 'pymorphy3'`**

```powershell
python -m pip install -r requirements.txt
```

**`CUDA out of memory`**

Уменьшите `--batch` до 128 или модель до `--d-model 160 --heads 4 --ff 640`.

**`torch.jit.script` падает**

Запустите `python smoke_test.py`. Он проверяет ровно тот путь, который
использует экспорт. Не добавляйте в модель операции, которых нет в
smoke-тесте: PyTorch Mobile 2.1.0 поддерживает не всё.

**На Android модель не загружается**

- Проверьте, что `sent.ptl` и `vocab.txt` действительно лежат в
  `app/src/main/assets/sentence/`.
- Посмотрите `adb logcat -s SentenceBuilder`.
- Убедитесь, что APK пересобран после копирования.
- Если ошибка связана с версией оператора, экспортируйте модель в окружении
  с PyTorch 2.1 (Python 3.11) или рассмотрите ExecuTorch. Текущий экспорт
  использует только стандартные операции (`bmm`, `softmax`, `layer_norm`,
  `gelu`, `embedding`, `linear`), но мобильный runtime 2.1.0 всё равно
  стоит проверить на конкретном телефоне.

**Кнопка пишет «Модель предложений не установлена»**

Это ожидаемо, пока вы не обучили модель и не скопировали `sent.ptl` и
`vocab.txt` в assets. Приложение при этом работает.

**Модель выдаёт бессмыслицу**

- Использован случайный/необученный чекпоинт.
- `vocab.txt` не совпадает с данными обучения.
- Слишком мало данных или эпох. Смотрите `exact` в `train_log.txt`.

**Кириллица в консоли выглядит как `????`**

Это кодировка консоли, а не данных. Используйте `chcp 65001` или смотрите
файлы в Android Studio/VS Code.
