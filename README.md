# Sign Language Translator

Android-приложение, которое распознаёт жесты по камере телефона и показывает
слово и три самых вероятных варианта с уверенностью.

Модель: **R3D-18** (torchvision), вход `1×3×16×112×112`, 100 классов,
предобучение на Kinetics-400, дообучение на датасете Slovo.

## Сборка и запуск

Требования:

- JDK 17+ (проверено на JDK 25);
- Android SDK с build-tools 36 и platform 37;
- Gradle wrapper уже в проекте.

```bash
# Windows
gradlew.bat :app:assembleDebug

# Linux/macOS
./gradlew :app:assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Быстрый способ открыть: Android Studio → **Open** → выбрать папку проекта
(ту, где лежит `settings.gradle.kts`) → дождаться Gradle sync → Run.

Подпись debug-ключа. Если ставите поверх другой сборки, сначала удалите
старую версию приложения (ключи разные).

## Модель и словарь

- `app/src/main/assets/classes.txt` — 100 слов в том порядке, в котором их
  возвращает модель. **Порядок менять нельзя**, иначе слова перепутаются.
- `app/src/main/assets/r3d18_slovo_100.ptl` — lite-интерпретатор PyTorch
  (`.ptl`), собранный из `r3d18_slovo_100words_best.pth`.
- Экспорт делался так: `torch.jit.trace` → `_save_for_lite_interpreter`.
  `optimize_for_mobile` **не использовался**: в текущей версии PyTorch он
  менял выходы модели (argmax менялся).

Если нужно пересобрать `.ptl` из чекпойнта:

```python
import torch
from model import R3D18  # ваша архитектура

ckpt = torch.load("r3d18_slovo_100words_best.pth", map_location="cpu")
net = R3D18(num_classes=100)
net.load_state_dict(ckpt["model_state"])
net.eval()

example = torch.rand(1, 3, 16, 112, 112)
traced = torch.jit.trace(net, example)
traced._save_for_lite_interpreter("app/src/main/assets/r3d18_slovo_100.ptl")
```

## Что изменено относительно старой версии

Коротко (подробно — в `docs/IMPROVED-README.md`):

1. **Поворот кадра** по `ImageProxy.imageInfo.rotationDegrees`.
   CameraX отдаёт кадр в ориентации сенсора, на портретном телефоне это 90°.
2. **Предобработка как при обучении**: resize короткой стороны до 128 →
   центральный кроп 112×112 (раньше кадр сжимался целиком и пропорции ломались).
3. **Скользящее окно**: буфер ~3 с, окно ~2.4 с, из окна равномерно берутся
   16 кадров. Раньше брались 16 подряд идущих кадров (~0.5 с) — модель видела
   только начало жеста.
4. **Softmax + EMA + порог**: показываются вероятности, а не сырые логиты;
   сглаживание по времени; порог уверенности 0.35; top-3 варианта.
5. **Lite-модель**: `LiteModuleLoader` + `.ptl` вместо полного `Module.load`
   с `.pt`.
6. **Камера**: задняя по умолчанию, кнопка переключения на переднюю,
   портретная ориентация, учёт системных отступов.
7. **Надёжность**: копирование модели во временный файл с переименованием,
   обработка ошибок native-библиотек, ограничение числа потоков PyTorch.

### Замеры на датасете Slovo (200 клипов, по 2 на класс)

| Вариант | Top-1 |
|---|---:|
| Правильный pipeline (128 → crop 112, 16 кадров на клип) | **69.0 %** |
| Сжатие всего кадра в 112×112 | 60.0 % |
| 16 подряд идущих кадров | 37.5 % |
| Приближение старого приложения | 28.0 % |

На полном тесте (500 клипов) исходная модель даёт **74.6 %**.

Важно: это метрики на датасете. На реальной камере точность ниже из-за
другого фона, света, ракурса и человека.

## Видео и слова

`docs/video_to_word.txt` — по одной строке на видео:


числом кадров и разрешением.

`E:\Programs\project\train` и `E:\Programs\project\test`.

Пересобрать списки:

```bash
python tools/build_lists.py
```

## Ограничения

- 100 слов фиксированы словарём модели. Для других слов нужны новые записи
  и дообучение.
- Нет класса «жеста нет»: модель всегда выбирает одно из 100 слов, поэтому
  порог 0.35 — единственная защита от ложных срабатываний.
- Дообучение на 1 эпоху в прошлый раз «сожгло» модель (25 % на тесте),
  поэтому в сборке используется исходный чекпойнт (74.6 %).

## Что нужно для дальнейшего улучшения

1. 10–20 клипов на каждое целевое слово: тот же телефон, то же освещение,
   длительность 1.5–3 с, жест целиком.
2. 20–30 клипов «нет жеста».
3. Точный список целевых слов.
4. Модель телефона, версия Android, камера, ориентация.
5. Logcat или видео с ошибкой: какой жест показан и что вывело приложение.
